# Kickoff brief

Ky's request that started the project on 2026-10-29, saved here so it outlives the session
that planned it. The original is first, then the same request as a list of constraints.

## The request, as Ky wrote it

> I want to create an app for my Mom to use to watermark her photos that she takes on her
> iphone. I think ideally it would not directly access her camera, but instead allow her to
> select photos she has already taken, one or more than one at a time, and do some
> positioning for a watermark to apply to all selected photos in the same location, or an
> option to allow "interesting" processing of each individually selected image to
> automatically place the watermark in a chosen "optimal" location (as judged by a vision
> model of some sort).
>
> It would be great if nothing needed to leave her phone - so that new copies of the images
> can be stored without internet connection.
>
> She uses an iphone, although it would be cool if it could work for my android as well.
> Importantly, it will need to be able to work with the photo file formats generated by the
> iphone.
>
> I don't think it's important for this to be a web piece - native iphone or maybe react
> native would probably be better choices. But you should first break down exactly what all
> capacities will be needed for the app first, and then research the best
> frameworks/languages/etc based on the requirements.
>
> This app should start super bare-bones, but I'd like to be able to easily customize it with
> feedback from my mom as well.
>
> Research current tools on the market that do this and their featuresets so that we can
> attain parity with standard tooling. In my previous searches, I haven't found anything
> *free* that does this well, but I know there are other tools on the market. For now, I'm
> not trying to *compete* - I just want to provide a permanently-free tool my Mom can use for
> her photography.
>
> Please generate lists of questions in a Socratic planning phase to get the project planned,
> with the end-goal being a comprehensive project **setup** (no *code* yet) - just folder
> structure and all appropriate agents.md and docs files that will be required for efficient
> work moving forward. Keep all research summarized in a folder that is gitignored but
> permanently accessible to future agents to inform their work moving forward.

## The same request as constraints

**Must have**
- Mom picks photos she has already taken. The app never uses the camera.
- One photo or many at a time.
- She positions a watermark once, and it goes on every selected photo in the same place.
- Optionally, the app places the mark on each photo by itself, at a spot a vision model
  judges best.
- Nothing leaves her phone. New copies are saved without an internet connection.
- It handles every photo format an iPhone produces.
- It's free for Mom, permanently.
- It starts bare-bones and is easy to change based on Mom's feedback.

**Nice to have**
- It also runs on Ky's Android phone.

**Not the goal**
- Competing with paid watermark apps. Parity with standard tools is the bar.
- A web app. Ky's first instinct was a native iPhone app or React Native. The planning log
  records how that held up against the other constraints.

**How Ky wants to plan**
1. Break down every capability the app needs, then research frameworks and languages
   against that list.
2. Research the watermark tools on the market and their feature sets.
3. Run a Socratic planning dialogue in rounds of questions.
4. End with the project set up: folders, AGENTS.md, and docs, but no code.
5. Keep the research summarized in a gitignored folder that future agents can read.
